01 / 按任务选路

小事直接做，复杂的先想清楚。

不必每次跑完整套流程。检查做到哪一步，取决于改动和风险。

  1. 01

    说清改哪里

    例如调整文案、修正一个已知行为。

  2. 02

    直接实施

    范围明确，就不额外写需求和方案。

  3. 03

    做相应检查

    行为改动做针对性验证，文案改动检查展示。

  4. 04

    按需提交

    准备提交时检查改动，再按你的授权执行。

已有的需求、方案和授权会接着用。只有影响业务含义、权限或不可逆操作的关键缺口，才需要补充确认。

拿不准下一步？说 用 dev-auto 看看下一步该做什么。它只推荐下一步，不会自动执行其他 skill。

开始前，你可能还想知道。

这是一个新的编程软件吗？

它是一套给 AI 阅读和执行的开发规则，安装在你已有的 Claude Code 或 Codex 中。你仍在原来的项目和工具里工作，模型也由你的运行环境选择。

需要记住 13 个 skill 的名字吗？

不用全部记住。先按场景描述任务，也可以点名相应 skill。拿不准时，说“用 dev-auto 看看下一步该做什么”，它会推荐下一步。

它会自动帮我提交代码吗？

是否提交取决于你的授权。提交前检查和生成 commit message 都不等于执行提交。已经明确要求的操作会沿用授权继续，不会在每个阶段重复询问。

升级会改掉我项目里的规则吗？

升级 skill 不会自动覆盖项目中的 CLAUDE.md 或 AGENTS.md。如果仓库模板更新了，需要你对比后按需同步自己的项目规则。
