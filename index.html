闭环门禁 · 为什么不是裸写

无门禁靠运气， 有门禁把返工挡在第一行代码之前。

AI 写代码越来越快，但真正消耗时间的是需求没对齐、修 Bug 只改表面、以及没人把关的盲目提交。切换下方模式，直接看一条任务在两种模式下的真实走向。

dev-auto

智能路由导航

基于当前证据推荐下一步该用哪个技能，只建议不越权执行。
dev-design-context

设计上下文沉淀

沉淀视觉语言、组件资产与约束到 .design-context.md，避免 UI 跑偏。
dev-grill-docs

需求与接口对齐

拷问边界并生成需求文档；UI/API 对接默认交付离线红框 HTML 报告。
dev-spec

Spec 兼容入口

等价于 dev-grill-docs --spec-only，平滑兼容老提示与已有文档流。
dev-plan

技术实施方案

复杂或高风险功能先拆解可执行蓝图与回滚边界，再进入编码。
swagger-doc-skill

API 契约查询

直连 Swagger / OpenAPI / Knife4j，提取模块、接口与完整 DTO 类型。
dev-image-to-code

看图实现页面

按设计图还原真实可交互控件（input/tab/select），并在真实浏览器核验。
dev-tdd

测试驱动实现

行为改动优先用有意义的测试锁住结果，小步实现，不写无意义样板测试。
dev-fix

根因排查修复

先复现、追到 root cause，再给最小范围修复与回归测试，拒绝表面打补丁。
dev-verify

交付前实证验证

宣称完成前必跑实证检查，展示真实输出并如实声明验证盲区。
dev-code-review

Diff 风险评审

提交前只读审查 Git Diff，拦截逻辑缺陷、回归隐患与误混调试文件。
dev-commit-writer

提交说明生成

根据当前 Diff 生成清晰规范的 Commit Message，只起草不擅自提交。
dev-finish

分支收尾交付

核验通过后，严格按用户授权完成本地 commit、merge、push 或 PR。
没有匹配的技能，试试搜索 fix、swagger 或 review。

安全与操作边界

哪些能直接做， 哪些必须等你拍板。

把 AI 的操作按风险划成三档：只读查询绝不改业务代码，受控开发落盘留痕，提交与推送必须先评审、经你授权才放行。点击左侧任意一档，看右侧实时动作。

DEV-CODE-REVIEW · 提交前拦截 待你拍板

提交前检测到 2 项风险，已暂停 commit

[P1] order.ts:88 空数组导出未判空会抛异常
[P2] 暂存区混入未跟踪调试文件 debug.json

未获明确授权前，不会执行 git commit 或 push。

两项高频专项交付

UI / API 联调

红框对齐离线报告

dev-grill-docs 产出可离线转发的单文件 *-integration.html，红框对照页面控件与后端接口缺口，发给后端一眼对清。

2 分钟试用

状态 · 证据 · 校准

每个阶段都说得清。 缺什么、改了哪、验没验，一眼看见。

SPEC-ANCHORED

产物跨阶段复用

已确认的需求、方案与授权沿用到底，不在每个阶段反复追问同一件事，跨会话交接也有据可依。

RISK-PROPORTIONAL

按风险缩放流程

不是繁琐教条：范围清晰的小改动直接实现并检查，涉及权限、数据或不可逆操作才拉起完整门禁。

MODEL-AGNOSTIC

不绑模型，可校准

不锁定特定模型版本；切换或升级底层模型后，可用仓库内置的校准用例检验实际决策质量。
